# fastFix

先在設定頁設好「哪個網站改哪個專案」。之後在那個網站上，**按住 Alt 點一段字** → 打新的字 → Enter。
那個專案原始碼裡的那段字就被換掉了。
改完幾處，按一次「送出」：一個 commit 加一次 push。

不用開編輯器，不用叫 AI。改字本來就只是「找到、換掉」。

```
按住 Alt 點標題
  立即免費開始
  ┌──────────────────────┐
  │ 先用再說               │
  │ [A−][A+] [細][粗] [■]  │
  │ Enter 送出 · Esc 取消 │
  └──────────────────────┘
改過的地方圈虛線、上線後字才變 · 左下角：已改 3 處，還沒送出 [送出]
```

- 只想改其中幾個字：先選取那幾個字，再 Alt + 點。
- 同一個框裡也能調這段字的樣子：`A−` `A+` 字大小、`細` `粗` 粗細、色塊是顏色。按了畫面當場變，
  Enter 才寫回原始碼，Esc 就還原。只改樣子、不改字也可以。
  它會照專案原本的寫法寫回去：Tailwind 的專案換 class（`text-lg` → `text-xl`），其他的寫在那個元素的 `style` 上。
- 專案是設定，不是操作的一部分：設定頁（`http://127.0.0.1:4480/setup`）有一張「網域 → 專案」的表，用之前先加好。
  它只會動那個網站設定的那一個專案，不會去別的專案找。沒設定的網站不能改，只會提示你去設定。
- 專案裡有好幾處同一段字 → 用那段字在頁面上的前後文判斷是哪一處；真的分不出來才列出檔名、行號讓你點。
- **送出** = 一個 commit（`chore: 網頁改字 N 處`）加 `git push`，然後做這個網站在設定頁設好的「送出後」動作，
  最後一直看那個網站，直到它真的顯示新的字。左下角會照實顯示走到哪：
  `送出中…` → `已送出，等網站更新`（一條會動的進度條，不數秒） → `已上線 ✓`（接著自己重新整理）。
  等超過 5 分鐘會改說網站還是舊的，讓你選再看一次或不等了；叫部署那一步失敗會直接說，可以再叫一次。

## 送出後：讓網站真的變成新的

每個網站在設定頁多一欄，三選一：

| 設定 | 送出後做什麼 | 適合 |
|---|---|---|
| push 就會自己部署 | 什麼都不用做 | push 會觸發部署的站（Vercel、有接 webhook 的 CloudPipe 專案）、本機開發伺服器 |
| 叫 CloudPipe 部署 + 專案代號 | 打 CloudPipe 的部署 API | push 不會自己部署的 CloudPipe 專案 |
| 跑一個指令 | 在專案資料夾裡跑那個指令（不等它跑完） | 其他情況。例如 fastFix 自己：`node scripts/restart.js` |

怎麼知道上線了：腳本每 5 秒抓一次你改字的那一頁（用你瀏覽器的身分，所以要登入的頁面也行），
頁面裡沒有就再看它載入的 script。只看「新的字出現了沒」，所以跟背後用什麼部署無關。
只改樣式、沒改字的送出沒有字可以比對，只會說已送出。

## 兩個零件

| | 是什麼 |
|---|---|
| `fastfix.user.js` | 裝進 Tampermonkey 的那支。只做一件事：每次開網頁去本機服務拿 `client.js` 來跑，所以裝一次就好，之後不用更新 |
| `client.js` | 真正做事的程式：接 Alt + 點、畫輸入框、把「舊字 → 新字」送出去。改了它，重新整理網頁就是新的 |
| `src/fix/element.js` | Tailwind + JSX 專案改樣式：用頁面上的標籤與 class 認出是原始碼裡哪個標籤，換掉它的 class |
| `server.js` | 本機服務：只聽 `127.0.0.1:4480`，在你的 repo 裡找字、換掉、commit、push。Node，零依賴 |

## 安裝

需要 Node 20 以上、git，瀏覽器裝好 Tampermonkey。

```bash
npm run init        # 產生 .env（隨機金鑰），已經有就不動
npm run autostart   # 放一個開機自動啟動的捷徑，並且現在就啟動
```

然後瀏覽器開 `http://127.0.0.1:4480/setup`：

1. 按「安裝腳本」，Tampermonkey 跳出來按安裝。
2. 回到設定頁按 `F5`，看到「已連上」就完成。金鑰是腳本自己從設定頁拿的，不用複製貼上。
3. 在同一頁的「哪個網站改哪個專案」加上你的網站：填網域（例如 `localhost:3000`）、選專案資料夾，按加入。

不要自動啟動：`powershell -File scripts/autostart.ps1 -Remove`。只想手動跑：`npm start`。

## 改不了、不會動的

改不了（會把一句給 AI 的指令放進剪貼簿，貼給它就能改）：

- 字是程式拼出來的，或來自資料庫、設定檔。
- 一次選取跨了好幾個元素（中間夾著標籤）。

樣式另外改不了的：這段字不是單獨放在一個元素裡、class 是程式組出來的、字的大小在不同螢幕寬度各有設定
（`md:text-2xl` 這類）。它會直接告訴你原因。

不會動：

- 有你還沒 commit 的修改的檔。
- 壓縮過的檔（`.min.*`）、超過 1MB 的檔、git 沒追蹤的檔。
- 新的字裡多了原本沒有的 `< > { }`、引號、反斜線或換行（可能弄壞程式）。

還沒有「放棄修改」：改錯就再改一次，或在那個專案裡 `git checkout -- 檔名`。

## 服務

| | | |
|---|---|---|
| `GET /health` | 不用金鑰 | 活著嗎 |
| `POST /fix` | 要金鑰，JSON | `{ text, to, url, pick? }` → 在原始碼裡把字換掉 |
| `POST /style` | 要金鑰，JSON | `{ text, look: { fontSize?, fontWeight?, color? }, url, pick? }` → 改那段字所在元素的樣式 |
| `POST /submit` | 要金鑰，JSON | `{ url }` → commit 加 push，做「送出後」動作，回這次送出的狀態（`delivery`）|
| `POST /landed` | 要金鑰，JSON | `{ url, result: "live" \| "dismissed" }` → 網站已經顯示新的字，或不等了 |
| `GET /pending?host=` | 要金鑰 | 還沒送出幾處，以及上一次送出還在等的狀態 |
| `GET /setup` | 只給本機直接開 | 設定頁：網域對專案的表、安裝腳本 |
| `POST /setup/sites`、`POST /setup/sites/remove` | 只給設定頁的表單 | 加、移除一筆網域對專案 |
| `GET /fastfix.user.js` | 不用金鑰 | 裝進 Tampermonkey 的那支（裡面沒有金鑰） |
| `GET /client.js` | 不用金鑰 | 那支腳本每次開網頁來拿的程式（裡面沒有金鑰） |

金鑰用 `Authorization: Bearer <FASTFIX_TOKEN>`。POST 只收 `application/json`：網頁可以偷偷跨站送
`text/plain`，但送 JSON 加金鑰標頭會被瀏覽器擋下來，所以別的網頁沒辦法叫它改你的檔。

設定（`.env` 或環境變數）：

| | 預設 | |
|---|---|---|
| `FASTFIX_TOKEN` | 必填 | 沒有就不啟動 |
| `PORT` | 4480 | |
| `HOST` | 127.0.0.1 | |
| `FASTFIX_ROOTS` | 這個 repo 的上一層資料夾 | 你的專案放哪。裡面每個 git repo 都會出現在設定頁的專案清單；多個資料夾用 `;` 分開 |
| `FASTFIX_HOME` | `~/.fastfix` | 設定與狀態檔（網域對應哪個專案、送出後做什麼、還沒送出的修改、上一次送出的狀態） |
| `CLOUDPIPE_URL` | `http://localhost:8787` | 有網站設成「叫 CloudPipe 部署」才用得到 |
| `CLOUDPIPE_TOKEN` 或 `CLOUDPIPE_CONFIG` | 無 | CloudPipe 的金鑰；或 CloudPipe `config.json` 的路徑（讀裡面的 `serviceToken`，不用抄一份） |

## 測試

```bash
npm test
```

涵蓋單一命中（別的專案有同一句也不動）、沒設定專案的網站、原始碼跨行、用前後文分辨同一句、多處挑選、找不到、危險符號、不碰髒檔、送出、push 失敗可重試、金鑰、設定頁的表單與拒絕情況；樣式在 Tailwind 專案與一般 HTML 專案的寫回方式、改不了時的回覆；送出後的狀態、叫 CloudPipe 部署、跑指令、叫部署失敗後重叫、設定頁存「送出後」。
腳本本體是用無頭瀏覽器實跑驗的（沒設定被擋 → 設定頁加專案 → Alt + 點 → 改 → 畫面變 → 送出 → 遠端有 commit），還沒放進 `npm test`。
