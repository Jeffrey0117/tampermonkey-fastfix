# fastFix — 設計

2026-11-19。MVP，先玩玩看。

## 為什麼

改網站上的字，本質是「找到那個字串、換掉」。交給 AI 做，錢不是花在取代，是花在找位置、
來回好幾趟、以及每開一次對話的固定成本。所以這種修改不經過 AI：在網頁上按住 Alt 點那段字、打新的字，
本機服務自己去原始碼找到並換掉。零 token。

## 目標 / 不做

- 做：改畫面上看得到、原始碼裡也原樣存在的字；多處修改累積起來一次送出（一次 commit、一次 push、一次部署）。
- 不做（這一版）：CSS、跨元素的選取、程式拼出來或資料庫來的字、放棄還沒送出的修改、HTML entity 對應。
- 不可以：改到別人還沒 commit 的工作、把會弄壞程式的符號塞進原始碼、任何網頁都能偷偷叫它改檔。

## 做法（Jeff 選的）

考慮過三種：

1. **點字就改，累積後一次送出** ← 選這個。改五處只部署一次。
2. 改一個推一個。最簡單，但連改會連續部署。
3. 整頁編輯模式。之後做 CSS 會長在這上面，但要多做很多；文字版用順了再升級。

第一版是做在「強力右鍵」的選單裡（選字 → 右鍵 → 改這段字）。Jeff 看了說不要放那裡、另寫一支、
要 fastFix 的感覺，所以獨立成這個 repo：自己的腳本、自己的服務（port 4480），
入口改成 Alt + 點（不用先選字；有選字就只改選到的那幾個字）。強力右鍵那邊已還原。

「哪個網站對應哪個專案」不做設定檔（Jeff 明講：到處都能按，不是自己的站改不了就好）。
選單項目在所有網頁都出現；服務拿那段字去 `FASTFIX_ROOTS`（預設：這個 repo 的上一層資料夾）
底下每個 git repo 找。改成功一次之後記住「這個網域 → 這個 repo」，之後只找那個 repo，找不到才再全部找。

## 行為

- `POST /fix { text, to, url, pick? }`
  - 一處命中 → 直接換，回 `done` 與「還沒送出」的數量。
  - 多處命中（≤12）→ 回 `choose` 與清單（repo、檔、行號、那一行），帶 `pick` 再送一次。超過 12 → `toomany`。
  - 沒命中 → `notfound`；腳本把一句給 AI 的指令放進剪貼簿。
  - 新的字帶進原本沒有的 `< > { } \` " ' \\` 或換行 → 422，不改。
  - 那個檔有不是這個工具造成的未 commit 修改 → 409，不改。
- `POST /submit { url }`：那個網域對應的 repo，把改過的檔做成一個 commit（`chore: 網頁改字 N 處`）再 `git push`。
  push 失敗時修改留在「還沒送出」，可以再按一次。
- `GET /pending?host=`：還沒送出幾處。
- 三條路都要金鑰；POST 只收 JSON（網頁沒辦法跨站偷送）。

比對：網頁會把換行與縮排顯示成一個空白，所以任何一段空白都對得上任何一段空白。
只找 git 有追蹤的文字類檔案（html、js、ts、tsx、vue、md、json…），跳過 `.min.*` 與超過 1MB 的檔。
git worktree（`.git` 是檔案）不算一個專案，避免同一份程式出現兩次。

狀態放 `~/.fastfix/state.json`（`FASTFIX_HOME` 可改）：網域對應、還沒送出的清單。

## 腳本這邊

Alt + 點一段字 → 那段字下面跳出輸入框（已填好原本的字）→ Enter 送出。成功後把畫面上的字當場換掉，
左下角出現「已改 N 處，還沒送出 [送出]」。只有改過字的網域，載入頁面時才會去問還有沒有沒送出的。

## 我自己定的（Jeff 沒講，可以改）

- 入口用 Alt + 點（Jeff 只說要 fastFix 的感覺）。
- 送出前不跳 diff：每一處都是親手改的。
- 多個 repo 都有同一段字時用清單挑，挑過就記住。
- commit 訊息格式與「會弄壞程式的符號」清單。

## 驗證

- `npm test`：服務端 9 個情境（單一命中、跨行、多處挑選、找不到、危險符號、髒檔、送出、push 失敗、金鑰）。
- 腳本：無頭瀏覽器實跑（Alt + 點 → 改 → 畫面變 → 送出 → 遠端有 commit），還沒放進 `npm test`。

## 2026-11-19 改版：專案是設定，不是操作

第一版沒有「專案」的概念：拿被點的那句話去所有專案找，找到就改，改過一次記住網域。實際用起來是錯的：
同一句話在兩個專案各有一份時，它跳出清單問要改哪個。Jeff 的判斷：這等於開發者沒開工作區就在編輯；
而且「選專案」不該出現在操作流程裡，是用之前就該設好的設定。

改成：

- 設定頁有一張「網域 → 專案」的表（表單直接送到服務，跟設定頁同一道防線：只限本機直接開，外加頁面帶的金鑰）。
- `/fix` 只在那個網域設定的專案裡找。沒設定就回 `unset`，腳本只提示去設定頁，不在當下問。
- 服務不再自己學網域對應，也不再掃所有專案。
- 同一個專案裡同一句話有多處：腳本把那句話在頁面上的前後各 60 個字一起送來，服務看每一處在原始碼的前後文
  有多像（越近的字分數越高），有唯一最高分就直接改，分不出來才列清單。清單只顯示檔名、行號和那一行，不再整段折行。

## 2026-11-19 加上：字的樣子（大小、粗細、顏色）

Jeff 要「CSS 的部分」。我提過兩版都被否決：把 class 與 CSS 規則列出來改（「不可能秀原始碼給 user，
那我幹嘛不開 VS Code」）、另外跳一個七個旋鈕的外觀面板（「就說了改文字而已」）。

我的解讀（Jeff 沒逐項確認）：這支工具只管「文字」，CSS 也只做文字本身的樣子，而且不另開介面。

- 介面：Alt + 點出來的同一個框，輸入框下面一排 `A− A+ 細 粗 色塊`。按了直接改頁面上那個元素的 inline style 當預覽，
  Enter 連同文字一起寫回，Esc 還原。
- 大小照 Tailwind 的級距走（12、14、16、18、20、24、30…），這樣在 Tailwind 專案剛好對得上 `text-*`，其他專案就是 px。
- 寫回哪裡：只改「直接包著那段字的那個元素」的開頭標籤，不去動共用的 CSS 規則，所以只影響你點的那段字。
  - 專案有 tailwind（根目錄有 tailwind.config.* 或 package.json 提到 tailwindcss）→ 換或加 class：
    `text-<級距>` / `text-[Npx]`、`font-<粗細>`、`text-[#色碼]`。保留其他 class 和 `dark:` 之類的變體。
  - 其他 → 加或更新 `style="…"`。
- 改不了就講原因（回 `cant`）：字不是單獨在一個元素裡、class 或 style 是程式組的、大小有螢幕寬度變體、
  非 Tailwind 的 JSX。
- 樣式和文字各算一筆「還沒送出」，一起 commit。

沒做：間距、背景、圓角、排版；改共用的 CSS 規則。

## 2026-11-19 加上：送出之後（部署與修改狀態）

Jeff：「這工具要配合自動部署的工具」。核准的方向（原話整理）：兩個都要。對使用者來說重點不是部署不部署，
而是「到底有沒有修改成功」，所以要有一個修改的狀態並顯示出來；也要主動去叫部署。
只改樣式、沒改字的情況他沒提過，怎麼做都可以。

做法：

- **狀態**：每個專案一筆「上一次送出」（`state.json` 的 `deliveries`）：
  `waiting`（已 push、已叫部署，網站還沒變）→ `live`（看到網站顯示新的字）或 `dismissed`（不等了）；
  叫部署那一步失敗是 `failed`，再按一次只重叫部署、不會再 commit。
- **主動叫部署**：是每個網站的設定（設定頁那一列的最後一欄），不是操作時問：
  push 就會部署（預設）／叫 CloudPipe 部署某個專案代號／跑一個指令。
  CloudPipe 的金鑰從 `CLOUDPIPE_TOKEN` 或 `CLOUDPIPE_CONFIG` 指到的 config.json 讀。
- **怎麼判斷上線**（我的決定）：由油猴腳本去抓改字的那一頁，找新的字；頁面沒有就看它載入的 script（含往下一層的 chunk）。
  在瀏覽器裡做而不是在服務裡做，因為要登入才看得到的頁面只有瀏覽器抓得到。跟部署工具無關。
  每 5 秒一次，5 分鐘後停下來改說「網站還是舊的」。上線後自己重新整理（輸入框開著就只給按鈕）。
- 每筆修改記下是在哪一頁改的（`page`），送出後就去那一頁找；同一段字連改兩次只找最後的樣子。
- 只改樣式的送出：沒有字可比對，只顯示已送出。

已知的限制：新的字如果本來就出現在那一頁別的地方，會太早判定上線；字藏在兩層以外才載入的 chunk 裡會等到逾時。

## 2026-11-19 修正：頁面只顯示真的上線的東西

Jeff：「上線才改網站上文字比較好，user 才能確認真的改了」「幾秒別寫，進度條，不然很躁」。

- 改完不再當場把頁面上的字換掉，樣式預覽也還原；改過的那一段只圈一圈虛線。字變了就代表真的上線了。
- 頁面還顯示舊字時再點它改一次：服務順著之前的修改找到它現在在原始碼裡的樣子來改（只點其中一部分就沒辦法，回 stale）。
- 等待時不數秒，改成一條來回跑的進度條。
- 輸入框裡有「送出」：改完直接送；Enter 是先改、晚點一起送。
